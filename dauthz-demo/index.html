DAuthZ — Ceremony Demo

The production flow: the service hands out a cyfron://auth link, a wallet signs it and the browser finishes the sign-in on its own. Here dauthz-gate is the service (verifying with dkms instead of cyfron-serviced) and dkms auth respond is the wallet.

Step 1 — Run the service

Create the service identifier (once), then start dauthz-gate from the repository root. It serves this page too, so open the demo at http://localhost:8088/:

dkms identifier init -a demo-service --witness-url http://172.17.0.1:3232 --witness-url http://172.17.0.1:3233 --watcher-url http://172.17.0.1:3235
cargo run -p dauthz-gate -- --config dauthz-demo/gate.demo.toml serve
Checking for dauthz-gate…

Step 2 — Create your identifier

The wallet side is a dkms identifier with a witness, so the service can resolve it:

dkms identifier init -a demo-entity --witness-url http://172.17.0.1:3232 --witness-url http://172.17.0.1:3233 --watcher-url http://172.17.0.1:3235

Step 3 — Passport optional

The gate can also require a credential: a passport issued by a demo authority to your identifier. Signing in then proves both who you are and that you hold a passport.

Issue one (the script creates demo-authority on its first run and writes the proof and the gate policy under target/dauthz-demo/):

dauthz-demo/passport.sh "Ada Lovelace" GB

Then restart the gate with the passport policy:

(set -a; . target/dauthz-demo/passport.env; set +a; cargo run -p dauthz-gate -- --config dauthz-demo/gate.demo.toml serve)

Restart without the env file to go back to the open policy.

Step 4 — Sign in

The button opens the gate's login page. There, press Copy URL (the Connect button needs a cyfron:// handler) and answer the link with dkms while the page waits:

dkms shows which service is asking and asks before it signs. The login page notices the answer within a second and brings you back here.
